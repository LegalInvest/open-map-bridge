## 1. 核心判断

数字化只是把对象、时间、空间、状态和证据变成结构化事实；可视化让人知道“现在发生了什么、哪里异常、下一步是什么”；自动化让系统在安全边界内持续推进，只有授权、冲突、高风险或低置信例外才交给人。

OpenMapBridge 的目标闭环应当是：

```text
合法图源输入
  → 事实数字化（解析、状态、来源、能力、日期、AOI、回执）
  → 决策可视化（进度、地图、时间、差异、证据、风险、下一动作）
  → 安全自动化（探测、绑定、选四期、质检、对齐、续跑、导出）
  → 人只处理授权、秘密、风险与事实解释
```

这条路线不改变当前最高优先级：先把同一个已确认奥维兼容 `sourceId` 安全绑定到真实运行时能力。可视化和自动化必须消费真实状态事件，不能用合成大屏掩盖真实图源仍为 `metadata-only`。

## 2. 当前基线与主要缺口

| 能力 | 当前事实 | 成熟度 | 下一目标 |
|---|---|---:|---|
| 图源数字化 | QR/`.ovmap` 可离线解析、预览、确认并保存；本地加密 vault 已 deployed；DNS/IP 固定传输代码已 main | L1 可见事实＋vault deployed | 把安全传输接入凭证注入、最小探测和运行时绑定 |
| 历史影像可视化 | 合成源已有四屏、卷帘、时间轴、同步视角、缺帧提示 | L2 交互可视化 | 真实源状态、质量和证据同屏 |
| 四期自动选择 | 动态 20 年窗口和四个唯一日期已自动选择 | L2 规则自动化 | 按可用性、日期可信度、覆盖和内容差异评分 |
| 运行过程可视化 | 四步准备度驾驶舱、状态、是否外联和下一动作已进入 main | L1 main | 接入真实探测、日期和帧质量事件 |
| 失败恢复 | run 原子持久化和同输入去重已通过 CI；没有步骤级续跑/取消 | L0/L1 | 可恢复工作流、只重试失败步骤和取消 |
| 证据与结果 | 有回执模型和变化观察面板 | L1 | 来源链、帧质量、比较结论与外部证据联动 |
| 运维可观测 | 测试和 CI 可用，运行时业务指标不足 | L0/L1 | trace ID、任务耗时、失败分类和护栏指标 |

成熟度定义：L0 仅有数据；L1 事实可见；L2 系统给出建议并执行低风险步骤；L3 用户一次触发即可安全跑完整闭环；L4 可批量无人值守且异常自动升级。V0/V1 目标到 L3，不追求未经治理的 L4。

## 3. 用户最终看到的产品

### 3.1 首页任务驾驶舱

首页不再只显示“图源导入/历史影像”两个孤立工作台，而显示一条真实任务链：

```text
① 已解析 → ② 已授权 → ③ 安全检查 → ④ 能力探测 → ⑤ 日期目录
→ ⑥ 自动选四期 → ⑦ 影像加载与质检 → ⑧ 对齐比较 → ⑨ 证据/导出
```

每一步必须显示：状态、开始/结束时间、耗时、输入输出摘要、是否产生外部请求、错误类别、重试次数、下一动作和回执 ID。未知显示“未知”，不能显示 0 或绿色成功。

### 3.2 “一键生成四期”主动作

用户选中已确认图源并框选区域后，首要动作是“一键生成四期”。系统自动：

1. 校验图源能力和 AOI 版本。
2. 如需秘密或内网授权，暂停并显示唯一人工步骤。
3. 受控探测并绑定运行时适配器。
4. 获取最近 20 个完整自然年的日期目录。
5. 选择最多四个唯一候选。
6. 请求最少必要瓦片并验证非空、可解码、覆盖 AOI 且内容不重复。
7. 冻结同 AOI、同投影、同 ViewState 的比较。
8. 展示四屏、卷帘、时间轴、质量标签和回执。

### 3.3 结果页从“看图”升级为“看事实”

四张图之外，增加：

- 年份可用性热力带：available/unknown/missing/failed 分开。
- 帧质量卡：请求日期、拍摄日期或未知、瓦片成功率、覆盖率、内容指纹、来源和版权。
- 变化矩阵：岸线、水面、围网、建设等“可见对象”按起止日期登记；算法只生成候选，不自动写因果。
- 来源链抽屉：从 QR/`.ovmap` 解析器、source ID、AOI 版本到每帧回执可追溯。
- 下一最佳动作：补凭证、确认范围、重试失败帧、补外部证据或导出报告，只显示当前最相关的一项。

## 4. 自动化状态机

系统采用 `AutomationRun`，而不是在前端串联多个临时请求。当前先实现不发网的 `source-readiness` 准备度求值，完整状态机按后续真实工作流扩展。

### 4.0 当前已实现候选子集

```text
confirmed source
  → source-confirmed
  → network-policy（静态，零 DNS/HTTP）
  → credential-readiness（只读脱敏需求与 active vault 实际命中）
  → runtime-binding（只读 registry）
  → completed | awaiting-intervention | blocked
```

输入指纹同时包含源配置事实、active vault 是否存在同 UUID 凭证和运行时 ID/availability；同一事实重复点击返回原 run，不重复写入。每步 `externalRequest=false`。这只回答“下一步为什么还不能探测/出图”，不回答服务器是否可达、瓦片是否有效。

### 4.1 运行状态

```text
draft → awaiting-authorization → queued → running
      → awaiting-intervention → running
      → completed | partial | failed | cancelled
```

### 4.2 步骤状态

```text
pending → running → succeeded
                 ↘ retryable-failed → running
                 ↘ blocked
                 ↘ skipped（必须有可审计原因）
```

每个步骤使用稳定幂等键：`runId + stepKind + sourceId + aoiVersion + inputHash`。刷新、重启或重复点击不能重复创建同一外部请求；恢复时只重跑未完成或明确可重试步骤。

### 4.3 人工门

只有以下事件停下来问人：

- 声明对图源具有使用权。
- 输入或更新凭证，秘密不进入普通任务载荷。
- 明确允许合法企业内网主机。
- AOI 与已确认版本冲突。
- 自动选择置信不足，需要用户选择日期。
- 将“可见变化”升级为污染、养殖或开发等因果解释。

其余解析、探测、日期获取、选四期、加载、质检、重试、回执和恢复均应自动执行。

## 5. 数据和接口建议

### 5.1 新业务对象

`AutomationRun` 目标：运行 ID、流程类型、source ID、AOI ID/版本、状态、创建/更新时间、当前步骤、进度、人工门、结果和 trace ID。当前准备度 V1 尚不含 AOI、进度、结果和 trace。

`AutomationStep` 目标：步骤类型、状态、尝试次数、幂等键、开始/结束时间、输入/输出引用、错误代码、是否产生外部请求和恢复建议。当前 V1 以 run 级 input fingerprint 去重，尚无 step 独立幂等键和输入输出引用。

`FrameQuality`：date ID、日期精度、成功/失败瓦片数、AOI 覆盖率、内容指纹、空白/重复判断和可选云量；未知字段保持 null。

`InterventionRequest`：所需角色、原因、风险、可选动作、截止时间和决策回执；不得保存明文秘密。

### 5.2 接口形态

接口可借鉴 OGC API - Processes 的 `process → execution → job → status/results/cancel` 模型：

```text
POST /api/v1/processes/four-frame/execution
GET  /api/v1/jobs
GET  /api/v1/jobs/{jobId}
GET  /api/v1/jobs/{jobId}/events
GET  /api/v1/jobs/{jobId}/results
POST /api/v1/jobs/{jobId}/resume
POST /api/v1/jobs/{jobId}/cancel
```

V0 用现有本地原子 JSON 仓库存放小型任务事实，先证明旅程；并发、多实例或长周期运行再迁移 SQLite/持久工作流引擎，不提前引入重基础设施。

当前已实现候选接口：

```text
GET  /api/v1/processes
POST /api/v1/processes/source-readiness/execution
GET  /api/v1/jobs
GET  /api/v1/jobs/{jobId}
```

创建接口只接受已保存 source ID。events/results/resume/cancel 与 four-frame process 尚未实现。

### 5.3 时空资产兼容

对已验证帧提供 STAC-compatible 描述候选：AOI geometry、datetime、projection、license/provider、thumbnail/本地 asset link。它是开放出口，不取代内部 source 权限、凭证和加载回执，也不得泄露奥维私有上游地址。

## 6. 四期自动选择升级

当前“时间上等距且唯一”保留为确定性基线，再增加可解释评分：

```text
score = 时间代表性
      + 可用状态
      + 日期可信度
      + AOI 覆盖率
      + 与已选帧的内容差异
      - 空白/重复惩罚
      - 云量或季节不可比惩罚（仅在有真实元数据时）
```

任何未知项不按 0 分处理，而是标记“不参与该项评分”。系统必须展示为什么选择这四期，并允许用户改选；改选后保留自动建议与人工裁决。

## 7. 可观测性

先用现有结构化事件账本实现业务可观测，再按规模接入 OpenTelemetry：

- Trace：一次“一键生成四期”从导入源到四帧结果的完整链路。
- Metrics：运行成功/部分/失败、各步骤耗时、人工等待、重试次数、上游请求放大、可比期数和假成功数。
- Logs：只记录稳定错误码、run/step/receipt/trace ID 和脱敏上下文。

前端驾驶舱消费的是真实任务事件，不从日志文本猜状态。OpenTelemetry JavaScript 的 traces/metrics 当前可作为后续稳定接入点；日志继续以项目结构化账本为真值。

`SLICE-AUTOMATION-RUN-001B` 继续与 `SLICE-V0-IMPORT-002` 同步：FIX-BATCH-012–014D 的加密 vault、同 UUID 引用、请求计划、凭证注入、DNS/IP/peer 固定传输、脱敏 ProbeResult 和非时序 map-tiles 已包含在腾讯 current `67a6a0e`，但尚未成为本任务的可恢复步骤。FIX-BATCH-015 帧质量已 deployed；FIX-BATCH-016 严格比较回执仅 local-verified。真实源、人工门决策、resume/retry/cancel 和完整一键四期仍须独立晋级。

当前 001A 完成结果：一个 confirmed source ID 可在零外联条件下准确停在凭证、安全或运行时阻塞；它不能推进到 ready，也不能替代真实源探测。

### P1：一键四期与断点续跑

把日期目录、自动选四期、四帧加载和比较回执编排为一个可恢复任务；刷新或网关重启后继续，失败只重试对应步骤。

### P2：结果解释与开放出口

增加质量卡、来源链、变化候选、证据门、STAC-compatible 元数据和报告/图片导出。MP4/GIF 必须在真实四期旅程稳定后实施。

### P3：批量与高级分析

在单区域真实 accepted 后，再做区域批次、定时监控、变化检测、通知、云端执行和插件化算法。任何因果判断仍需独立证据与人工裁决。

## 9. 验收建议

### AC-019 任务状态真实可见

从真实 QR/`.ovmap` 确认开始，驾驶舱逐步显示每个后台事实；故意制造凭证缺失、403、429、单帧空白和网关重启，状态、错误、重试和下一动作均准确，其他成功步骤不回退。

当前阶段候选只覆盖 confirmed、静态策略、凭证需求、runtime binding 和重开恢复；403/429/空白帧仍待 001B/四期切片。

### AC-020 一键四期

用户只完成授权、选择 source、框选 AOI 和必要人工门；系统自动得到最多四个真实、唯一、可解码且非空帧并生成比较回执。缺四期时显示真实数量和原因。

### AC-021 断点续跑与幂等

任务运行中重启网关或重复点击，恢复后不重复外部探测、不重复保存图源、不丢失已成功帧；只重试未完成或明确可重试步骤。

### AC-022 可解释选择与证据边界

四期选择理由、日期精度、质量字段和未知项可见；算法生成的变化只能是候选。没有独立证据时，UI/API 均不能输出确定污染或过度开发结论。

## 10. 采用与不采用

立即采用：现有 OpenLayers 四屏/卷帘/共享视角；现有状态机和回执；OGC Processes 的任务资源形态；STAC 的开放时空元数据思想；结构化业务事件。

延后采用：Temporal 等独立持久工作流平台、完整 OpenTelemetry 后端、批量遥感处理集群。只有单机状态仓库无法满足并发、恢复或可观测目标时再引入。

不采用：由前端按钮串联不可恢复请求、把日志当任务状态、用合成大屏冒充真实源、自动抓取 20 年全域瓦片、没有证据的污染因果判断。
