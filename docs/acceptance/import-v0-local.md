## 已证明

- 二维码图片真实经 ZXing 解码；图片原文件不送入网关。
- 摄像头成功、取消、报错和卸载都走停止控制/媒体轨道的代码与单元测试；无摄像头可等价改用图片。
- `ovobj` 的普通模板变体与用户真实 `at/ad/al + opaque ul` 变体都能生成统一 `MapSourceDefinition` 预览。
- `at/ad/al` 值和不透明 `ul` 不进入预览、开放定义、回执或 JSON 状态；候选被准确标记为需要凭证/奥维桥接。
- `.ovmap` 按魔数、声明长度、zlib 头、输出上限、解压比、记录数/长度、字符串长度和 UTF-8 做有界解析。
- 检查阶段没有 DNS/HTTP 上游调用；授权未勾选时前后端均拒绝保存。
- 合成 QR 完成 `preview → confirmed → 本地原子保存 → 页面刷新恢复`；状态仍是 `confirmed`，不是 `rendered/saved/accepted`。

## 尚未证明

- 用户真实历史二维码的私有认证值尚未进入本地保险库，因此没有对其源站探测或真实瓦片渲染。
- 没有启用官方奥维第三方接口；回环绑定、日期目录和四日期不同瓦片仍未验证。
- 未实现 URL/SSRF 最终策略、最小探测、瓦片代理、投影修正、撤销、开放导出和 `.sdb` 数据导入。
- `.ovmap` 只兼容已验证的 `record37-zlib` 家族，不代表所有年代/版本。

结论：`SLICE-V0-IMPORT-001` 的解析、安全预览、授权保存和浏览器入口达到 `local-verified`；AC-002、AC-003 达到本地验收。AC-001 只完成真实二维码到安全预览，真实瓦片和最终 `rendered+saved` 仍 blocked；整体产品未达到用户 accepted。
